# AsthmaAware — Deliverable 6: `GET /dashboard`

The backend endpoint behind the authenticated dashboard. For the user's current location it returns:

- the **current risk** as a 0–100 score and a level (`low` / `moderate` / `high`);
- the **top environmental contributors** to that risk (up to 3);
- the user's **personalized risk for every hour of today**.

This is the first working version. The API and its internal steps are real; the inputs they depend on (forecast tiles, per-user sensitivity weights, the model's output scale) are **mocked**, so each one can be swapped for the real component later without changing the endpoint or its response.

| Piece | Status now | Replaced later by |
|---|---|---|
| Grid lookup (lat/lon → grid cell) | Mock 0.05° grid over Georgia | The real forecast tile grid |
| Hourly forecast (`g` and `z` per hour) | `app/data/mock_forecast.json` | Forecast tiles from cloud storage |
| User sensitivity weights (`w_u`) | `app/data/mock_user_personalization.json` | The real personalization store |
| Signed-in user | Always `demo-user` | Authentication |
| Severity → 0–100 score | Placeholder linear scale | The model's real severity range |
| Personalization formula, contributor ranking | **Final** | — |

This folder is self-contained. It does not import from `backend/app/`.

## Running it

Requires Python 3.11+ (the current FastAPI/Starlette releases need it). From `backend/dashboard/`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

uvicorn app.main:app --reload
```

Then open:

- <http://127.0.0.1:8000/dashboard?lat=33.7490&lon=-84.3880> — the endpoint

## Request

`GET /dashboard?lat=<latitude>&lon=<longitude>`

| Parameter | Required | Valid range |
|---|---|---|
| `lat` | yes | −90 to 90 |
| `lon` | yes | −180 to 180 |

There is deliberately **no `user_id` parameter**: the user comes from `get_current_user_id()` in [app/api/dashboard.py](app/api/dashboard.py), so one caller can never request another user's risk. It returns `demo-user` until authentication exists; adding auth only changes that function.

## Response

Example for downtown Atlanta at 4 pm on 2026-10-15 (`hourly_risk` shortened):

```json
{
  "location": {
    "lat": 33.749,
    "lon": -84.388,
    "grid_cell_id": "ga_02424"
  },
  "forecast": {
    "forecast_run_id": "2026-10-15T04:00:00Z",
    "valid_at": "2026-10-15T20:00:00Z"
  },
  "risk": {
    "score": 67,
    "level": "moderate"
  },
  "contributors": [
    { "feature": "o3", "contribution": 0.32 },
    { "feature": "pm25", "contribution": 0.31 },
    { "feature": "pollen", "contribution": 0.18 }
  ],
  "hourly_risk": [
    { "timestamp": "2026-10-15T04:00:00Z", "risk": 38 },
    { "timestamp": "2026-10-15T05:00:00Z", "risk": 38 },
    "...",
    { "timestamp": "2026-10-15T20:00:00Z", "risk": 67 },
    "...",
    { "timestamp": "2026-10-16T03:00:00Z", "risk": 38 }
  ]
}
```

| Field | Meaning |
|---|---|
| `location.lat`, `location.lon` | The coordinates you sent |
| `location.grid_cell_id` | The grid square containing them, e.g. `ga_02424` |
| `forecast.forecast_run_id` | Which forecast run the numbers came from. Mock: the start of today (Atlanta time) |
| `forecast.valid_at` | The hour the current `risk` and `contributors` describe (the current hour) |
| `risk.score` | Current personalized risk, 0–100 |
| `risk.level` | `low` (0–39), `moderate` (40–69) or `high` (70–100) |
| `contributors` | Up to 3 factors raising the user's risk right now, largest first. `contribution` is that factor's share of the total increase (0–1) |
| `hourly_risk` | Personalized risk for each hour of today, in time order |

All timestamps are **UTC, ISO 8601, with a `Z` suffix**. Feature names match the AirNow pipeline: `pm25`, `o3`, `no2`, `temperature`, `humidity`, `precipitation`, `wind`, `pollen`, `ndvi`.

## Errors

| Situation | Status | Body |
|---|---|---|
| `lat`/`lon` missing, not a number, or out of range | `422` | FastAPI's standard validation error |
| Valid coordinates outside Georgia | `404` | `{"detail": "Location (40.7128, -74.006) is outside the supported area (Georgia)."}` |

Any location inside Georgia gets a full response.

## How the risk is computed

The model's eventual formula, for one place and hour:

```text
y = g + w_u · z
```

- **`g`** — the general prediction: expected symptom severity for an average person at that place and hour.
- **`z`** — the standardized environmental features: how unusual each factor is right now. `0` is typical, `+1` is one standard deviation above typical.
- **`w_u`** — the user's sensitivity to each factor. Positive means a higher value raises their risk; negative means it lowers it (wind and rain clear the air).
- **`w_u · z`** — multiply each factor by the user's sensitivity to it and add them up: the user's personal adjustment on top of `g`.

[app/services/dashboard_service.py](app/services/dashboard_service.py) builds the response from one function per step:

| Function | What it does |
|---|---|
| `resolve_grid_cell(lat, lon)` | Finds the grid square, or `None` outside Georgia |
| `get_forecast_for_cell(grid_cell_id, time_range)` | Hourly `g` and `z` for that square over a time range |
| `get_user_personalization(user_id)` | The user's weights `w_u` |
| `calculate_personalized_risk(general_prediction, environmental_features, user_weights)` | `g + w_u · z` |
| `risk_score_from_severity(prediction)` | Severity → 0–100 score |
| `get_top_contributors(environmental_features, user_weights)` | Ranks factors by `w_f × z_f` |
| `get_dashboard(lat, lon, user_id, now=None)` | Runs all of the above and assembles the response |

To plug in a real component, replace the body of its function and keep its inputs and outputs the same.

### Risk score (placeholder)

`score = round(y / 4.0 × 100)`, clamped to 0–100. The `4.0` (`SEVERITY_SCALE_MAX`) is an assumed top of the severity scale. It and the level bands (`RISK_LEVEL_THRESHOLDS`) are named constants at the top of the service, to be updated once the model's real output range is known.

### Contributors

Each factor's impact is `w_f × z_f`. Only factors with a **positive** impact count as contributors, since a factor lowering risk isn't something "behind" it. The top 3 are returned, each as its share of the total positive impact. A user with no personalization weights gets no contributors; their risk is just `g`.

### Today and now

- "Today" is the **calendar day in Atlanta** (America/New_York), so daylight saving is handled. `hourly_risk` normally has 24 entries; on the two clock-change days it has 23 or 25.
- `risk`, `contributors` and `forecast.valid_at` all come from the **current hour**.
- The mock forecast stores hours by local hour of day, not by date, so it produces data for whatever today is.

### Grid

A mock grid of 0.05° squares (about 5.5 km) over a rectangle around Georgia: 30.35–35.00 N, −85.61 to −80.84 W, 93 rows × 96 columns. Row 0 is the northern edge, the same convention as the ConvLSTM grid in `backend/ingestion/grid_resample.py`. A cell's id is `ga_` plus its zero-padded index `row × 96 + col`.

## Known limitations

- **All numbers are mock data.** The forecast, the user weights and the risk scale are stand-ins.
- **Georgia is a rectangle.** Small corners of neighbouring states (Florida, Alabama, Tennessee, the Carolinas) inside it count as supported. A real state outline can replace `GEORGIA_BOUNDS` later.
- **One demo user** until authentication exists.
- **Only two locations have their own mock profile.** Everywhere else in Georgia shares the default profile.
- **The mock grid isn't the team's existing grid.** The database (`backend/db/`) holds the ConvLSTM's 56×96 grid over a smaller Atlanta box, with integer cell ids. The dashboard's Georgia grid is separate until the real forecast tile grid is defined.
